# Test environment on AWS (single host, under $20/month)

DECISIONS D-072. Region **ca-central-1**. For testing with **seed data only**: no real customer
data, no real email. Production keeps the design in `deployment.md`.

## Not included (on purpose)
No load balancer, NAT gateway, RDS, ElastiCache, WAF, CloudFront, S3 document storage or SES.
Consequences: one server (no high availability), restore from snapshot (up to 24 h of data
lost), 2 GB RAM (a handful of testers; no load tests).

## Security notes
- Inbound only 80/443; no SSH port. Shell access: `aws ssm start-session --target <instance>`.
- IMDSv2 only. The instance role can read only `/corridor/staging/*` parameters and make the
  three Cognito admin calls the API needs, on this pool only.
- Secrets (database passwords, Django key, field encryption key) are generated by Terraform,
  stored as SSM SecureString, written at boot to root-only files on the host. They are also in
  Terraform state: the state bucket is private, encrypted, versioned and TLS-only.
- The stack runs with `DJANGO_ENV=staging`: debug off, secure cookies, local sign-in refused.
- Email stays suppressed (`EMAIL_SENDING_ENABLED=false`).
- **Cognito sends its own invitation email** when the API creates a user (`admin_create_user`).
  That is a real email: invite only addresses you own, with approval (MASTER_PROMPT §0.3).
  Phone-number invitations need SMS (not configured), so test drivers sign in by email.

## Steps (each `apply` needs explicit approval)
1. **Images.** The `publish-images` workflow builds linux/arm64 images after CI passes on main
   and prints their digests in the run summary. In GitHub → Packages, set `corridor-backend` and
   `corridor-web` to **public** once (the host pulls them without credentials).
2. **Bootstrap (once).**
   ```
   cd infrastructure/terraform/environments/bootstrap
   terraform init && terraform plan -var account_id=<12 digits>     # review, then apply after approval
   ```
3. **Test environment.**
   ```
   cd ../test
   cp test.tfvars.example test.tfvars                               # fill in; git-ignored
   terraform init -backend-config="bucket=<state_bucket output>"
   terraform plan -var-file=test.tfvars -out=test.plan              # review, then apply after approval
   ```
4. **First boot** takes ~10 minutes (updates, Docker, PostGIS image build, migrations). Follow it
   with `sudo tail -f /var/log/corridor-bootstrap.log` in a Session Manager shell.
5. **First company.** In a Session Manager shell:
   `sudo docker compose -f /opt/corridor/compose.yml exec api python manage.py create_tenant --slug demo --name "DEMO — Freight" --owner-email <your email> --reason "test env" --demo`
   (sends the Cognito invitation email to that address).
6. **Smoke test.** `https://<ip>.sslip.io/healthz/ready` returns 200, sign-in works, the public
   tracking page of a TEST shipment opens.

## Backup and restore (Phase 7 Done-when: tested once)
Restore = create a volume from the latest snapshot, stop the instance, swap the root volume,
start. To be exercised once after the first apply and recorded in PROGRESS.md.

## Tear down
`terraform destroy -var-file=test.tfvars` (after approval). The Cognito pool has deletion
protection and the root volume is kept on instance termination: both are removed deliberately,
not by accident.
